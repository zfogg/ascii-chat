# ascii-chat documentation workflow

ascii-chat documentation is generated by Doxygen from three complementary
inputs:

- Source comments and headers provide API, file, type, and symbol reference
  pages.
- `docs/topics/*.dox` provides curated, source-oriented Topics pages for
  architecture, ownership, protocols, subsystems, and developer workflows.
- `docs/*.md` provides focused authored guides, operational instructions,
  research notes, test records, and plans. Doxygen imports these as authored
  pages rather than treating them as source APIs.

`docs/topics/index.dox` defines Topic Categories, while `docs/topics.dox`
defines Topics. Put durable subsystem documentation in both indexes when it
belongs in the curated navigation. Link focused Markdown pages from the
appropriate category instead of exposing a flat collection of root-level pages
in the sidebar.

Before changing a public API, subsystem, transport, option, screen, or
workflow, inspect the existing topic and authored guides and update or create
the relevant page in the same change. Prefer a `.dox` Topic for architectural
truth and a Markdown guide for task-specific detail; keep them cross-linked and
do not copy stale implementation claims between them.

The generated site is built by the standalone CMake project in
`docs/CMakeLists.txt`. It configures Doxygen without configuring or compiling
the native application and writes the HTML under the selected build directory.
The repository's documentation workflow builds this project and deploys its
HTML artifact to GitHub Pages after a successful build.

Verify with the docs-only project in `docs/CMakeLists.txt`:

```sh
cmake -S docs -B build/docs-standalone -DASCII_CHAT_SOURCE_DIR=$PWD
cmake --build build/docs-standalone --target docs
```

Check generated HTML for broken links, topic placement, and stale claims before
committing. Verify the hosted page after documentation deployment completes.
